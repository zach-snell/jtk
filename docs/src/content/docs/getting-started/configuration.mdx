## Authentication

jtk supports two authentication methods: interactive login and environment variables.

### Interactive Login

```bash
jtk auth
```

You will be prompted for your Jira domain, email, and API token. The command also prints the exact granular scopes to select when creating your token.

Credentials are saved to `~/.config/jtk/credentials.json` with restricted file permissions.

### API Token Scopes

Create a **Jira** app token at [id.atlassian.com](https://id.atlassian.com/manage-profile/security/api-tokens). Select "Jira" as the app, then add granular scopes.

<Tabs>
<TabItem label="Read-only (18 scopes)">
```
read:me
read:jql:jira
read:issue-details:jira
read:issue-type:jira
read:issue-link:jira
read:issue-worklog:jira
read:issue.changelog:jira
read:issue.transition:jira
read:comment:jira
read:attachment:jira
read:project:jira
read:project-version:jira
read:status:jira
read:user:jira
read:permission:jira
read:board-scope:jira-software
read:sprint:jira-software
read:dev-info:jira
```
</TabItem>
<TabItem label="Full access (add 7 more)">
```
write:issue:jira
write:comment:jira
write:issue-worklog:jira
write:issue-link:jira
write:attachment:jira
write:sprint:jira-software
delete:issue:jira
```
</TabItem>
</Tabs>

<Aside type="tip">
jtk provides a **two-layer safety model**: token scopes control API access (403 if missing), and `/mypermissions` introspection dynamically hides mutation tools your Jira account lacks.
</Aside>

Check your auth status:

```bash
jtk status
```

Log out and remove stored credentials:

```bash
jtk logout
```

### Environment Variables

For CI/CD or ephemeral environments, set these environment variables:

```bash
export JIRA_DOMAIN="mycompany"
export JIRA_EMAIL="me@example.com"
export JIRA_API_TOKEN="ATATT3x..."
```

Environment variables take priority over stored credentials.

### Credentials File Format

```json
{
  "domain": "mycompany",
  "email": "me@example.com",
  "api_token": "ATATT3x...",
  "saved_at": "2025-01-15T10:30:00Z"
}
```

<Aside type="caution">
Never commit credentials to version control. The `credentials.json` file is saved with `0600` permissions (owner read/write only).
</Aside>

## MCP Client Configuration

To use jtk as an MCP server, configure your AI client:

<Tabs>
<TabItem label="Claude Desktop">
Add to `~/Library/Application Support/Claude/claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "jtk": {
      "command": "jtk",
      "args": ["mcp"]
    }
  }
}
```
</TabItem>
<TabItem label="Claude Code">
```bash
claude mcp add jtk -- jtk mcp
```
</TabItem>
<TabItem label="Cursor">
Add to `.cursor/mcp.json` in your project root:

```json
{
  "mcpServers": {
    "jtk": {
      "command": "jtk",
      "args": ["mcp"]
    }
  }
}
```
</TabItem>
<TabItem label="Environment Variables">
If you prefer environment variables over stored credentials:

```json
{
  "mcpServers": {
    "jtk": {
      "command": "jtk",
      "args": ["mcp"],
      "env": {
        "JIRA_DOMAIN": "mycompany",
        "JIRA_EMAIL": "me@example.com",
        "JIRA_API_TOKEN": "ATATT3x..."
      }
    }
  }
}
```
</TabItem>
</Tabs>

## Disabling Tools

You can disable specific MCP tools via the `JIRA_DISABLED_TOOLS` environment variable:

```bash
export JIRA_DISABLED_TOOLS="manage_worklogs,manage_attachments"
```

Or in your MCP client config:

```json
{
  "mcpServers": {
    "jtk": {
      "command": "jtk",
      "args": ["mcp"],
      "env": {
        "JIRA_DISABLED_TOOLS": "manage_worklogs,manage_attachments"
      }
    }
  }
}
```
